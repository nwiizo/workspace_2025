## 実践パターン集

### ✅ Good: 強結合は近くに配置

```rust
mod user_profile {
    pub struct User { /* ... */ }
    pub struct UserProfile { /* ... */ }

    impl User {
        pub fn get_profile(&self) -> &UserProfile { /* ... */ }
    }
}
```

### ✅ Good: 弱結合は遠くても可

```rust
// core/src/lib.rs
pub trait NotificationService {
    fn send(&self, message: &str) -> Result<()>;
}

// adapters/email/src/lib.rs
impl NotificationService for EmailService { /* ... */ }
```

### ❌ Bad: 強結合が遠距離

```rust
// src/api/handlers.rs
impl Handler {
    fn handle(&self) {
        // 別クレートの内部実装に直接依存 ❌
        let result = database::internal::execute_raw_sql(...);
    }
}
```

### ❌ Bad: 高変動コンポーネントに強結合

```rust
// ビジネスロジック（頻繁に変更される）
pub struct PricingRules { /* 複雑な実装 */ }

// 多数の場所で直接利用 ❌
impl Order {
    fn calculate(&self) {
        let rules = PricingRules::new();  // 強結合
        rules.apply(self);
    }
}
```

### ✅ Better: トレイトで隔離

```rust
pub trait PricingStrategy {
    fn calculate(&self, base: f64) -> f64;
}

pub struct Order {
    pricing: Box<dyn PricingStrategy>,  // 弱結合
}
```
