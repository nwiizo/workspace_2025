# 実測検証: actix-webアプリケーションでの性能評価

**検証環境**

- 日付: 2025 年 10 月 17 日
- ハードウェア: Apple Silicon (M-series)
- Docker 環境: Colima
- Rust: 1.83
- cargo-chef: latest-rust-1

**テストアプリケーション:**

- フレームワーク: actix-web 4.11
- 総依存関係数: 185 パッケージ
- アプリケーション種別: REST API（ヘルスチェックと CRUD エンドポイント）
- 主要依存関係: actix-web、tokio、serde、env_logger

### 検証結果の詳細

**テスト1: コールドビルド（初回ビルド）**
```
総時間: 1分33.56秒（93.56秒）

内訳:
- ベースイメージダウンロード: 約20秒
- 依存関係コンパイル: 約62秒（cargo chef cook）
- アプリケーションコンパイル: 約3.4秒
- イメージ組み立て: 約5秒
```

**重要な観察:** 依存関係が総ビルド時間の約 66%を占める。

**テスト2: ウォームビルド（変更なし）**
```
総時間: 1.172秒
```

- すべてのレイヤーが `CACHED` とマーク
- コールドビルドと比較して**80倍の高速化**
- コンパイルは一切発生せず

**テスト3: ソースコード変更のみ**

変更内容: `src/main.rs` にコメントを追加。

```

内訳:
- Plannerステージ: 約0.3秒（recipe.json再生成）
- 依存関係ビルド: キャッシュ済み（スキップ）
- アプリケーションコンパイル: 約3.16秒
- イメージ組み立て: 約0.8秒
```

**重要な観察:**

- 依存関係はキャッシュされたまま（recipe.json 変更なし）
- アプリケーションコードのみ再コンパイル
- コールドビルドと比較して**21.7倍の高速化**
- 依存関係のビルド時間の**97%を節約**

### 技術的な洞察

**recipe.jsonの動作:**

- すべての Cargo.toml マニフェストを含む
- バージョン固定のために Cargo.lock を含む
- JSON 形式で人間が読めてデバッグ可能
- 小さなファイルサイズ（約 3KB）、ステージ間のコピーが高速

**依存関係キャッシングメカニズムの確認:**
1. 最小限の有効な Rust プロジェクト構造を作成
2. ダミーソースファイルを生成（空の main.rs、lib.rs）
3. `cargo build` を実行して依存関係をコンパイル
4. ダミーアーティファクトを削除
5. `target/` ディレクトリにコンパイル済み依存関係を残す

これにより、Docker は依存関係レイヤーを独立してキャッシュできます。

### 推奨事項

**cargo-chefを使用すべき場合:**

**強く推奨:**

- ✓ 中規模から大規模の Rust プロジェクト（100 以上の依存関係）
- ✓ 頻繁なビルドを伴う CI/CD パイプライン
- ✓ 安定した依存関係ツリーを持つプロジェクト
- ✓ 高速な反復サイクルを必要とするチーム

**価値がない可能性:**

- ✗ 非常に小規模なプロジェクト（20 未満の依存関係）
- ✗ 依存関係が常に変更されるプロジェクト
- ✗ 一回限りのビルド
