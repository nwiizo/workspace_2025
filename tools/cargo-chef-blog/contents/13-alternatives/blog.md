# 代替アプローチとの比較

**手動ダミーファイルアプローチ:**

- 偽の main.rs を作成
- 最初にマニフェストをコピー
- 依存関係をビルド
- ダミーファイルを削除
- 実際のソースをコピー

問題: 脆弱、ワークスペースで破綻、手動メンテナンスが必要、チームで説明・維持が困難。

**Docker外でビルド:**

- CI ランナーでビルド
- バイナリを Docker にコピー

問題: 再現性の喪失、アーキテクチャの不一致、最適化された Docker イメージを生成しない。

**sccache単独:**

- より細粒度のキャッシング
- sccache サーバーインフラが必要
- より複雑なセットアップ
- インクリメンタルコンパイルサポートなし

cargo-chef の利点: 外部インフラ不要、Docker のネイティブキャッシングを使用、理解が簡単、ワークスペースを自動処理、組み合わせた利益のために sccache と互換性あり。
